T-007 で決まった規約が**実装とテストに反映されているか**だけを見る検査。
`repo-explorer` が走査し、`reality-checker` が合否を出す。
**このスキルは実装を直さない。**

## 正となる規約（T-007 / 2026-07-27 決定）

`docs/01_requirements/scoring-requirements.md` の **§0 が各指標表に優先する**。

| #   | 決定                                                      |
| :-- | :-------------------------------------------------------- |
| 0.1 | 境界値は**下限以上・上限未満**（① の 20% ちょうどは 9点） |
| 0.2 | ① の表の穴は転記ミス。`0%〜2% → 1点` / `20%〜30% → 9点`   |
| 0.3 | ③⑤⑥⑨ は**値が負なら 0点**                                 |
| 0.4 | ③ の無配（配当性向 0% かつ配当額 0）は **0点**            |
| 0.5 | データ欠損は総合点で **0点として合算。分母は常に 100**    |

> ⚠️ **⑥ と ⑨ が未実装の間、総合点は最大 80/100 になる。**
> 総合点の隣に**有効指標数（例「有効 8/10」）が併記**されていることを
> 必ず確認する。無ければそれだけで不合格。

## 手順

### 1. 実装とテストを走査する — repo-explorer

Agent ツールを `subagent_type: repo-explorer` で起動する。

拾わせるもの。

- `src/lib/scoring/` 配下の指標ごとの関数（①〜⑩ のどれに対応するか）
- 各関数の戻り値の型（**`null` を返せるか**）
- `tests/` 配下で各関数を対象にしているテストと、そのテスト名

結論だけ返させる。

### 2. マトリクスを埋める

指標 × 4系統の表を作る。埋まっていないセルが検出結果。

| 指標               | 境界値ちょうど | 負値 | 無配(0) | 欠損(null) |
| :----------------- | :------------- | :--- | :------ | :--------- |
| ① 増配率           |                | —    |         |            |
| ② 連続増配年数     |                | —    |         |            |
| ③ 予想配当性向     |                | 要   | 要      |            |
| ④ 営業利益率       |                |      |         |            |
| ⑤ ROE 5年平均      |                | 要   |         |            |
| ⑥ 配当維持可能年数 |                | 要   |         |            |
| ⑦ 自己資本比率     |                |      |         |            |
| ⑧ 売上高成長率     |                |      |         |            |
| ⑨ MIX係数          |                | 要   |         |            |
| ⑩ 配当利回り       |                | —    | 要      |            |

「要」は §0.3 / §0.4 で **0点と明示的に決まった**もの。ここが欠けていたら
確実に不合格。「—」は負値が定義上ありえないもの。

### 3. 個別に確認する

- **境界値**: 区分の下限ちょうどが**上の点数**になっているか
  （`>=` で実装されているか）。①の 20% は 9点、10点ではない
- **① の表**: `0%〜2% → 1点`、`20%〜30% → 9点` に訂正済みか。
  原典の `1%` / `29%` が残っていたら不合格
- **負値**: ③⑤⑥⑨ が負のとき 0点を返すか。
  ③ と ⑨ は原典のままだと**赤字企業が満点**になる
- **欠損**: 個別指標は `null` を返すか。`0` で初期化していないか
- **総合点**: `null` を 0 として合算し、**分母が常に 100** か
- **表示**: 個別指標の `null` は `—`。`0点` や `0.00%` と出していないか

### 4. 合否を出す — reality-checker

Agent ツールを `subagent_type: reality-checker` で起動する。
渡すもの: マトリクス、走査で見つけたテスト名の一覧、
`npm test` の**実際の出力**。

```bash
npm test
```

既定は NEEDS WORK。合格には**テスト名と実行結果**が要る。
「テストがあるはず」を受け付けさせない。

### 5. 直さない

欠けているテストは一覧にして返す。実装が必要なら `impl-from-spec` に回す。

## 完了条件

- [ ] マトリクスの全セルが埋まっている（該当なしは「—」と明記）
- [ ] 「要」のセルにすべてテストがある
- [ ] ① の表の訂正（2% / 30%）が実装に入っている
- [ ] 個別指標が `null` を返せる型になっている
- [ ] 総合点の分母が常に 100 になっている
- [ ] 有効指標数の併記が実装されている
- [ ] `npm test` が exit 0

## 落とし穴

- **各指標表の記述をそのまま実装と照合しない。** §0 の決定が優先する。
  表には「0%〜25% → 10点」と書いてあるが、③ の赤字は 0点が正。
- **`docs/02_design/logic/dividend-yield-scoring.md` §6 は原典との差分**を
  記録したもの。原典の側を正としない。
- ⑥⑨ が未実装なのは現時点では正常。**未実装であること自体を不合格に
  しない。** ただし総合点が 80 上限になる旨の併記は必須。
