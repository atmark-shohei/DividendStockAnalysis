# 投資銘柄スコアリング 要件定義

> 出典: OneDrive「銘柄スカウティング」`docs/investment_scoring_requirements.md`（2026-07-26 取り込み）
> **スコア表の数値・閾値は原文から一切変更していない。** 投資判断に直結するため、
> 変更はユーザーの明示的な決定を必要とする。取り込み時に発見した不整合は
> 「§0 未解決の仕様曖昧点」に列挙してある。

本ドキュメントは、企業の財務データに基づき10個の指標でスコアリングを行うロジックを定義する。
**本プロジェクトにおける唯一の正解（Single Source of Truth）。**
実装・レビュー・テストは常にこのファイルを参照すること。

満点は 10指標 × 10点 = **100点**。

---

## 0. 仕様上の曖昧点と決定（2026-07-27 決着）

取り込み時に発見した5件の曖昧点は**すべて決着済み**。
**この節の決定は下の各指標表に優先する**（食い違う場合はこちらが正）。

> 🔴 **2026-07-27 追記: スコア基準の出典がもう1つ見つかり、10指標すべてで
> 閾値が食い違っている。** 本ファイルの表は**据え置き**（変更していない）。
> 相違の一覧と判断は
> [scoring-source-comparison.md](./scoring-source-comparison.md) にまとめてある。
> §0 の5件の決定はこの相違とは独立に有効。

| #   | 論点                           | 決定                                                         |
| :-- | :----------------------------- | :----------------------------------------------------------- |
| 0.1 | 境界値がどちらの区分に属するか | **下限以上・上限未満**                                       |
| 0.2 | ① 増配率の表の穴               | 転記ミスと確定。**0%〜2% → 1点 / 20%〜30% → 9点** に訂正済み |
| 0.3 | 負の値・赤字企業               | ③⑤⑥⑨ とも**値が負なら 0点**                                  |
| 0.4 | ③ の無配（配当性向 0%）        | **0点**                                                      |
| 0.5 | データ欠損の総合点への算入     | **0点として合算。分母は常に 100点**                          |

### 0.1. 境界値は「下限以上、上限未満」

各行は下限を含み上限を含まない。最上位行のみ「下限以上」、最下位行のみ
「上限以下」。したがって ① の 20% ちょうどは **9点**。

旧実装（[reference/legacy-web/](../../reference/legacy-web/README.md)）の判定関数が
すべて `>=` で書かれており、この解釈と一致していた。

実装時はこの規約をコード上のコメントに書き、**境界値ちょうどのテストを全10指標ぶん**
用意すること。

### 0.2. ① 増配率の表の穴は転記ミス（訂正済み）

原典では「1%以上2%未満」と「29%以上30%未満」がどの行にも該当しなかった。
上限値の転記ミス（1→2、29→30）と確定し、**下の ① の表は訂正済み**。
旧実装の `getDividendCagrScore()` に穴が無かったこと（`>= 20 → 9点`、`> 0 → 1点`）が
裏付けになった。他の9指標にこの穴は無い。

### 0.3. 負の値は 0点（③⑤⑥⑨）

| 指標               | 負になる条件                     | 決定    |
| :----------------- | :------------------------------- | :------ |
| ③ 予想配当性向     | EPS が赤字                       | **0点** |
| ⑤ ROE 5年平均      | 平均 ROE が負                    | **0点** |
| ⑥ 配当維持可能年数 | 債務超過（ネットキャッシュが負） | **0点** |
| ⑨ MIX係数          | PER が負（赤字）                 | **0点** |

原典のままだと ③ と ⑨ は「0%〜25% → 10点」「0倍〜10倍 → 10点」に該当し、
**赤字企業が満点**を取った。④⑦⑧ には「0%以下 → 0点」の行があるので、
③⑤⑥⑨ に無いのは記載漏れと解釈する。

> ③ について 0点とする決定を受け、**⑤⑥⑨ にも同じ原則を適用した。**
> ⑨ は ③ と構造的に同一の欠陥（負値が最上位区分に該当する）であり、
> 別扱いにする理由がない。⑤⑥ は表の範囲外で挙動が未定義だった。
> 意図と違えば指摘すること。

### 0.4. ③ の無配は 0点

配当性向 0%（＝無配）は原典では満点だった。高配当銘柄を探すシステムとして
意図に反するため **0点**とする。⑩ 配当利回りも 0点になるため、無配銘柄は
両指標で最低評価になる。

なお「無配銘柄をスクリーニング対象から除外する」案は採らない。減配・復配の
推移を追えなくなるため、対象には含めたうえで低く評価する。

### 0.5. データ欠損は 0点として合算（分母は常に 100）

- **総合点:** 計算不能な指標は **0点として合算**する。分母は常に 100点
- **個別指標の表示:** `0点` と表示してはいけない。**`—`（判定不能）** と出す。
  「計算できなかった」と「計算した結果が最低区分」は画面上で区別する
- **データ層:** 無配（0円）とデータ欠損（`null`）は引き続き区別する
  （`CLAUDE.md` の規約）。0 に丸めるのは総合点の集計時だけ

> ⚠️ **⑥ と ⑨ が未実装の間、総合点は最大 80点になる。**
> 分母が常に 100 なので、実装済みの8指標が全て満点でも 80/100 と表示される。
> 誤読を防ぐため、総合点の隣に**有効指標数（例「有効 8/10」）を必ず併記**すること。

## 1. 指標別 計算ロジックおよびスコア表

### ① 直近5年間の増配率（CAGR）

- **詳細仕様:** [dividend-growth-rate-scoring.md](../02_design/logic/dividend-growth-rate-scoring.md)

- **計算式:** $\text{CAGR} = \left( \frac{\text{昨年の配当金}}{\text{5年前の配当金}} \right)^{\frac{1}{5}} - 1$
- **使用データ:** 株式分割の影響を排除した「分割調整」列の値を用いる（§2.2 参照）
- **注意:** 5年前の配当金が 0 の場合はゼロ除算。計算不能として `null` を返すこと

| 増配率（下限） | 増配率（上限） | 点数 |
| :------------- | :------------- | :--- |
| 30%            | 以上           | 10   |
| 20%            | 30%            | 9    |
| 15%            | 20%            | 8    |
| 12%            | 15%            | 7    |
| 10%            | 12%            | 6    |
| 8%             | 10%            | 5    |
| 5%             | 8%             | 4    |
| 3%             | 5%             | 3    |
| 2%             | 3%             | 2    |
| 0%             | 2%             | 1    |
| -              | 0%以下         | 0    |

> ✅ 原典にあった穴（1〜2%、29〜30%）は上限値の転記ミスとして訂正済み（§0.2）。

### ⑥ 配当維持可能年数

- **詳細仕様:** [dividend-sustainability-scoring.md](../02_design/logic/dividend-sustainability-scoring.md)

| 6年                  | 8年                  | 6    |
| 5年                  | 6年                  | 5    |
| 4年                  | 5年                  | 4    |
| 3年                  | 4年                  | 3    |
| 2年                  | 3年                  | 2    |
| 1年                  | 2年                  | 1    |

> ✅ **債務超過（ネットキャッシュが負）の場合は 0点**（§0.3）。

## 2. システム UI およびデータ入力要件

### 2.1. データ入力方式（コピー＆ペースト）

ユーザーが IR サイト（IR BANK 等を想定）の配当履歴表をコピーし、Web 画面上の
テキストエリアに直接ペーストしてデータを入力できる機能を実装する。

**想定されるペーストデータの形式（TSV 状のテキスト）:**

```text
年度	区分	中間	期末	合計	分割
調整	配当
利回り	備考
2010年
3月	実績	6,500	-	13,000	10.83	2.69%	#1
2011年
3月	実績	6,500	-	14,000	11.67	2.72%	#1
...
```

### 2.2. データパース（解析）要件

ペーストされたテキストから、スコアリングに必要なデータを正確に抽出するパーサーを実装する。

- **行の結合と年度の抽出:** 「2010年」と「3月」が別々の行に分かれているケースがあるため、
  これらを結合して「2010年3月期」として認識する
- **「区分」の判定:** 同一年度に「予想」「修正」「実績」が混在している場合、原則として
  **「実績」** を優先して採用する（当期については最新の「予想」または「修正」を利用する）
- **分割調整後配当の取得:** CAGR（増配率）などの計算には、株式分割の影響を排除した
  **「分割調整」** 列の数値（例: `10.83`）を使用する
- **数値のクレンジング:** `6,500` のようなカンマ付き文字列、`-`（ハイフン）、
  `15#2` のような注釈記号付き文字列から、正確に数値を抽出する

> ⚠️ **`-`（ハイフン）は 0 ではなく「データなし」として扱うこと。**
> 0 に変換すると減配判定（②）と CAGR（①）が壊れる。§0.5 参照。

### 2.3. データ入力方式（CSV のドラッグ＆ドロップ）

Web 画面上に CSV ファイルをドラッグ＆ドロップできる専用エリアを配置する。
ユーザーが指定フォーマットの CSV をドロップすると、ファイル内容を読み込み、
自動でスコアリングを実行する。

**想定される CSV データの形式:**
先頭に銘柄名（例: `"9433 KDDI"`）が記載され、空行を挟んで
「業績」「財務」「CF」「配当」の4ブロックが続くフォーマット。

### 2.4. CSV からの指標計算要件

CSV の各ブロックから以下の値を抽出し、スコアリングを計算する。

| 指標               | 抽出元                                                                                           |
| :----------------- | :----------------------------------------------------------------------------------------------- |
| ⑤ ROE の5年平均    | 「業績」ブロックの `ROE` 列の直近5年分を平均                                                     |
| ⑦ 売上高の5年 CAGR | 「業績」ブロックの `売上高` 列                                                                   |
| ④ EPS の5年 CAGR   | 「業績」ブロックの `EPS` 列                                                                      |
| ③ 予想配当性向     | 「配当」ブロックの最新予想 `一株配当` と「業績」ブロックの最新予想 `EPS`（または `配当性向` 列） |
