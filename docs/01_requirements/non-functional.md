# 非機能要件

> ステータス: 🟡 draft（2026-07-28 一部更新）— 性能目標は仮。外部データ取得を前提にした記述を削除

## 正確性（このアプリで最重要）

金額の表示ミスは投資判断の誤りに直結する。機能より正確性を優先する。

- 金額・比率の計算に浮動小数点を使わない（整数の銭単位 or Decimal）
- 配当利回りの計算はゼロ除算・データ欠損を必ず処理する
- **無配（0円）とデータ欠損を区別する。** 欠損を 0 として表示しない
- 単位を必ず併記する（円 / %）。裸の数値を表示しない
- 表示するすべてのデータに取得時刻を紐付ける
- 株式分割・決算期変更をまたぐ比較で桁がずれないことをテストで担保する

## セキュリティ

- API キー・認証情報は環境変数から読む。コード・ログ・エラー応答に出さない
- API Route のエラー応答に内部情報（SQL・パス・スタックトレース）を含めない
- 入力は必ずサーバー側で検証する（クライアント検証だけに頼らない）

## 性能

| 項目                | 目標   | 状態  |
| ------------------- | ------ | ----- |
| 一覧表示（100銘柄） | < 1.0s | 🟡 仮 |
| 銘柄詳細表示        | < 0.5s | 🟡 仮 |
| スクリーニング実行  | < 2.0s | 🟡 仮 |

- 一覧取得で N+1 クエリを作らない

## 可用性・データ保全

- 取り込み失敗でも既存データを壊さない（トランザクション。実装: `D1CompanyRepository.save` の `db.batch()`）

## アクセシビリティ

- 増減・良否を色だけで表現しない（記号・文言を併記）
- 対話要素はキーボードで操作できる
- 表形式データは `<table>` で構造化する

## 保守性

- `src/domain/` のドメインロジックはテストで担保する
- 設計を変えたら `docs/02_design/**` も同時に更新する

## 法務・免責

- 投資助言・投資勧誘に該当する表現を出さない
- 免責文言を画面に常時表示する
