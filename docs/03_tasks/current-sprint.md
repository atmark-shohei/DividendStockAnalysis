## 今スプリントでやること

### T-001 データ源の決定 🔴

**これが決まらないと何も作れない。最優先。**

調べること:
- 配当実績（過去5〜10年）が取得できるか
- 権利確定日・支払日が取得できるか
- 予想配当と実績配当が区別できるか
- 利用規約上、このアプリの用途（個人利用の分析・DB 保存）が許されるか
- レート制限と費用

成果物: `docs/00_overview/system-architecture.md` の「データ源の検討」表を埋め、
1つに決めて理由を書く。

### T-003 / T-004 認証の要否と公開範囲 🔴

「自分だけがローカルで使う」なら認証は不要。決めたら
`docs/02_design/api/auth-api.md` と `docs/02_design/ui/pages/login-page.md` を
更新するか削除する。

### T-002 DB / ORM の決定 🔴

判断材料:
- 単一ユーザー・ローカル前提なら SQLite で十分か
- 金額を整数で持つので `FLOAT` 精度の問題は回避できる
- マイグレーション運用のしやすさ

### T-010〜T-013 開発環境の起動確認 🔴

```bash
npm install
npm run dev        # 起動するか
npm run typecheck  # 通るか
npm test           # 通るか
```

**通らなかったコマンドは `CLAUDE.md` の表から削除する。**
動かないコマンドを書いたまま残さない。

## メモ

- 金額は銭単位の整数。浮動小数点を使わない
- 無配（0円）とデータ欠損（null）を必ず区別する
- 予想配当と実績配当を混ぜない
