## 0. 結論（先に読む）

1. **design_mock は「画面と情報設計の正」として採用する。ただしスコア判定の数値・計算式は採用しない。**
   試作の `criteria` 配列は**4区分のプレースホルダ**で、正典（`01_requirements/scoring-requirements.md`
   の11段表）と全指標で食い違う。式にも誤り（⑨ MIX係数）がある。詳細は §2.4。
2. **試作は3つの既決事項に関わる。** 認証の導入（T-003/T-004）、ユーザーごとの閾値
   （[ADR-0005](../adr/0005-thresholds-fixed-for-now.md) の「追記」節が先送りしていた設計。
   [ADR-0012](../adr/0012-indicator-customization-scaling-and-denominator.md) で具体化済み。
   ADR-0005 の結論自体は覆さない）、総合点の分母固定（`scoring-requirements.md` §0.5）。
   **いずれも投資判断に直結するので、ADR を書いて決着させてから設計書を直す**（§3）。
3. **新規に必要な設計書は7本、改訂は9本、廃止・整理は3本**（§2）。
4. 着手順は **Phase 0（意思決定）→ Phase A（設計書）→ Phase B（実装）**。
   Phase 0 が終わるまで Phase A の一部（指標カスタマイズ・総合点）に着手しない。

### D-2. 「満点となる基準値」1つで11段の区分表をどう作るか ★最重要 ✅ 決定（2026-08-16）

> **決定: (a) 比例スケーリング。詳細は [ADR-0012](../adr/0012-indicator-customization-scaling-and-denominator.md)。**
> 現行表の満点境界を基準に、10境界すべてを `新基準値 ÷ 現行満点境界` 倍する。
> **保存前に `validateBands()` を必ず通す**（穴のある表は黙って `—` を出す）。
>
> `bands.ts` の実測により2点判明した（ADR-0012 に反映済み）:
>
> - **③予想配当性向は降順**（値が小さいほど高得点）だが**単調減少**なので、
>   最上位区分の上限（`25`）を満点境界としてそのまま比例スケーリングが成立する
>   （原典のような U字型ではない）。
> - **基準値は正でなければならない。** 0以下だと `scale ≤ 0` になり境界が崩壊する。
>   試作の数値入力 `min`（③⑥は `-100`）はそのままだと0以下を許してしまうため、
>   **ドメイン側で追加のガードが必要**（T-080・T-100 の受入基準に反映）。

試作は指標ごとに**値を1つ**（例: ROE 12.0%）入力させ「これで10点」とする。
正典の区分表は**10個の境界値で11段**。1値から11段をどう導くかが未定義。

| 案                                     | 内容                                                            | 評価                                                                  |
| :------------------------------------- | :-------------------------------------------------------------- | :-------------------------------------------------------------------- |
| (a) 比例スケーリング                   | 現行表の満点境界を基準に、全境界を `新基準値 ÷ 現行満点境界` 倍 | **推奨。** 表の形（幅の粗密）が保たれ、既存の11段テストが流用できる   |
| (b) 満点境界だけ上書き                 | 10点の下限だけ動かし、残り9境界は固定                           | 単純だが、基準値を下げると表が非単調になり `validateBands()` に落ちる |
| (c) 10境界すべてをユーザーに入力させる | 試作のUIと乖離。入力コストが高い                                | 不採用                                                                |

- **どの案でも `validateBands()` を保存前に必ず通す**（ADR-0005 の注記）。穴のある表は黙って `—` を出す。
- ⑨ MIX係数は設定不可（試作どおり derived）。③ は 10段で1点を返す経路が無い点を UI で誤解させない。

> domain 実装）が着手されるまで実際には固定のままであり、ADR-0005 の結論
> 「閾値は当面デフォルト固定」は今も事実として正しい。ADR-0012 は ADR-0005 の
> 「追記」節が先送りしていた設計を具体化しただけなので、**リンクを追記するにとどめた**
> （supersede は「決定を覆す」ときに使うもので、今回は約束を果たしただけ）。
