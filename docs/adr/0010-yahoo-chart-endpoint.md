# ADR-0010: Yahoo Finance のチャートエンドポイントを個人利用に限って直接叩く

- ステータス: ✅ 採用（実装は未着手）
- 日付: 2026-07-31
- 関連: [ADR-0007](./0007-irbank-json-direct-fetch.md)（同じ構図の先例）、
  [ADR-0008](./0008-frontend-domain-runtime-import.md)（**Yahoo を一度却下している**）、
  [market-data-source.md](../02_design/logic/market-data-source.md)

## 背景

[market-data-source.md](../02_design/logic/market-data-source.md) は、株価・配当履歴・
株式分割イベントを次のエンドポイントから取得する。

```
GET https://query1.finance.yahoo.com/v8/finance/chart/{code}.T
    ?range=max&interval=1mo&events=div%7Csplit
```

これは `yfinance`（Python ライブラリ）が内部で叩いているのと同じ URL である。
**Yahoo が公開している「API」ではなく、Web サイトが使う内部エンドポイント**であり、
`yfinance` 自身も Yahoo と契約関係を持たない非公式クライアントである。

構図は [ADR-0007](./0007-irbank-json-direct-fetch.md)（IRバンクの静的 JSON を
直接 fetch する）とほぼ同じだが、**規約面の状況は同じではない**（下記「ADR-0007 との違い」）。

### ⚠️ ADR-0008 が Yahoo を一度却下している

[ADR-0008](./0008-frontend-domain-runtime-import.md) の末尾は、PER/PBR の取得元として
Yahoo Finance を検討し、**却下**している。

> Cookie＋Crumb方式の認証が必要でステートフルな上に不安定（yfinance 自体の
> リポジトリに crumb 関連の不具合報告が継続的にある）と分かり、Cloudflare Worker
> （ステートレス）との相性が悪いため見送った。

**これは別のエンドポイントの話である。** 却下されたのは `quoteSummary`（PER/PBR などの
指標を返す）で、こちらは確かに Cookie＋Crumb を要求する。本 ADR が対象とする
`v8/finance/chart` は**認証を要求しない**。

実測（2026-07-30、9433 / 7203 / 8306 / 1301）:

| リクエスト                       | 結果         |
| :------------------------------- | :----------- |
| User-Agent なし                  | **HTTP 200** |
| `User-Agent: Cloudflare-Workers` | HTTP 200     |
| ブラウザ風 User-Agent            | HTTP 200     |

Cookie も Crumb も不要で、Workers の既定 `fetch` でそのまま通る。
ADR-0008 の却下理由（ステートフル・不安定）は本経路には当てはまらない。

> ⚠️ **2026-08-04 追記: 上表の「User-Agent なし → HTTP 200」は現在は再現しない。**
> 下記「2026-08-04 追記: User-Agent が必要になった」を参照。認証が不要である
> （Cookie も Crumb も要らない）点は今も変わらない。

## 決定

**`v8/finance/chart` を、個人利用に限って Worker から直接 fetch する。**

1. **個人利用に限る。** このアプリを不特定多数に公開しない。
   広告・課金を含む収益化をしない
2. **User-Agent を詐称しない。** UA 無しで 200 が返ることを実測済み。
   ブラウザを騙る文字列を送ると、規約の回避を意図したと解釈されうる
   - ⚠️ **2026-08-04 改定**（下記追記）: 「ブラウザを騙る文字列は送らない。ただし
     UA 無しでは Yahoo が 429 を返すため、`user-agent: node` を送る」に改める
3. **ユーザーの操作1回につき1銘柄1リクエスト。** 一覧の全銘柄を一括更新する
   機能・定期実行・クローリングは作らない
   （[market-data-source.md](../02_design/logic/market-data-source.md) §1.2 / §5.1）
   - ⚠️ **2026-08-07 追記: この決定#3は Yahoo Finance 経路に限る。**
     [ADR-0011](./0011-edinet-financial-history-api.md) が EDINET 経路について、
     docIDインデックス構築に限り日次バッチ（Cron Trigger）による全社走査を
     例外的に許可した。**Yahoo Finance のこの経路自体は変更しない**
     （非公式エンドポイントを定期実行する動機・正当化がEDINETとは異なるため）
4. **取得層とパース層を分ける**（ADR-0007 と同じ）。規約面で取得できなくなったときに
   前段だけ差し替えられるようにする

⚠️ **条文の適法性を確認したわけではない**（ADR-0007 と同じ立場）。
弁護士等の確認は取っていない。利用形態が個人利用を超えたら再判断する。

## 2026-08-04 追記: User-Agent が必要になった

**上の実測（2026-07-30）と決定#2 は、そのままでは動かなくなった。**
歴史的記録として元の記述は残し、ここに訂正を書く。

### 何が起きたか

`wrangler dev`（workerd）上で `GET /api/market-data/9433` が 502 になった。
サーバーログは `market data import failed source-unreachable`、応答時間 109ms
（タイムアウト5秒・リトライ待機1秒を経ていない速さ）で、
`chart-client.ts` の「429 を受けたら即座に諦める」パスだった。

### 実測（2026-08-04、銘柄 9433）

- **2026-07-30 の「UA なしで 200」は再現しない。** curl でも 429 になる
- **workerd の fetch は User-Agent を一切送らない。** ローカルのエコーサーバーで
  送信ヘッダーを実測した結果:

| ランタイム              | 送信ヘッダー                                                                               | Yahoo の応答 |
| :---------------------- | :----------------------------------------------------------------------------------------- | :----------- |
| Node fetch（undici）    | accept, accept-language, sec-fetch-mode, **user-agent: node**, accept-encoding, connection | **200**      |
| workerd（wrangler dev） | accept, cf-worker（**User-Agent が無い**）                                                 | **429**      |

- workerd 上で User-Agent だけを変えた検証:

| 条件                                         | 結果                    |
| :------------------------------------------- | :---------------------- |
| UA 無し                                      | **429**                 |
| `user-agent: node`                           | **200**（30,487 bytes） |
| `user-agent: DividendStockAnalysis/1.0`      | 200（30,487 bytes）     |
| `user-agent: node` + Node 同等の付随ヘッダー | 200                     |

**Yahoo の WAF が UA 無しのリクエストを 429 で拒否している。**

### 決定#2 の改定

> **2. ブラウザを騙る文字列は送らない。ただし UA 無しでは Yahoo が 429 を返すため、
> `user-agent: node` を送る。**

`DividendStockAnalysis/1.0` でも 200 が返ることを確認したうえで、`node` を選んだ
（Node の undici が既定で送っているのと同じ値であり、素性を偽らずに済む）。
ブラウザを騙る文字列を送らない、という決定#2 の趣旨自体は変えていない。

### 「見直しのトリガー」には該当しない

本 ADR の「Yahoo が `chart` エンドポイントに認証を要求し始める、または 429 を
恒常的に返す」というトリガーに、**今回は該当しない。**
UA を付ければ 200 が返るので、認証の要求でも恒常的なレート制限でもなく、
**データ源の見直しは不要**である。Cookie も Crumb も引き続き不要。

## ADR-0007（IRバンク）との違い

**Yahoo のほうが規約面で不利である。** 同じ「非公式エンドポイントを個人利用で叩く」
構図でも、次の点が違う。

|                    | IRバンク（ADR-0007）       | Yahoo（本 ADR）                                |
| :----------------- | :------------------------- | :--------------------------------------------- |
| 規約の条文         | **未確認**のままリスク受容 | **商用利用の禁止が明示されている**             |
| 公開・収益化する道 | 不明                       | **無い**（正規の再配布ライセンスが存在しない） |
| 認証               | 不要                       | 不要（`chart` に限る）                         |

J-Quants には「Pro を契約すれば外部配信できる」という正規ルートがあるが、
**Yahoo にはそれが無い**。したがって本経路は**公開路線では行き止まり**である。
将来このアプリを公開する判断をした場合、**この ADR ごと破棄してデータ源を
入れ替える**必要がある。

## 検討した代替案

- **案A: J-Quants API（ライト、月1,650円）** — 却下。銘柄名・株価は取れるが、
  データ保持期間が**5年前まで**で、本仕様の主目的である ② 連続非減配年数
  （10点に17年必要）が埋まらない。20年ぶんが要る Premium は月16,500円
- **案B: J-Quants Pro（法人向け）** — 却下。社内利用でも該当データセットが
  月50,000円から。外部配信は個別見積もり。個人の趣味プロジェクトの規模を超える
- **案C: EDINET（金融庁）** — 見送り。財務データは取れて二次利用も認められているが、
  **株価が無い**。配当も有報からの抽出になり XBRL のタクソノミ解析が要る。
  公開路線に舵を切るなら再評価する価値がある
  - ⚠️ **2026-08-07 追記: 「株価が無い」という却下理由は変わらないが、「XBRLの
    タクソノミ解析が要る」は無効化された。** [ADR-0011](./0011-edinet-financial-history-api.md)
    参照。EDINET API v2 は2024年4月以降、XBRLをタブ区切りCSVに変換済みのZIPを
    返すため、生XBRLの名前空間解析は不要と実測で確認した。**株価・配当以外
    （EPS・売上高の古い年度、貸借対照表2項目）に限って EDINET を採用**する
    （本ADRのスコープである株価・配当は変わらず対象外）
- **案D: 株価・配当も手入力のままにする** — 却下。② は18年ぶんの配当を要求するので、
  手入力は現実的でない

## 見直しのトリガー

次のいずれかが起きたら本 ADR を再検討する。

- **公開・収益化を検討する**（この時点で本経路は使えない。最優先のトリガー）
- Yahoo が `chart` エンドポイントに認証を要求し始める、または 429 を恒常的に返す
  - 📌 **2026-08-04 の 429 はこれに該当しない。** UA を付ければ 200 が返るため、
    認証要求でも恒常的なレート制限でもない（「2026-08-04 追記」参照）。
    `user-agent: node` を送っても 429 が続くようになったら、そのときは該当する
- Yahoo の利用規約が改定され、個人利用の位置づけが変わる
- 日本語の銘柄名・財務諸表まで必要になり、取得元を見直す動機ができる
