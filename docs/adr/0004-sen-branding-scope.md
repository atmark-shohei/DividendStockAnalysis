# ADR-0004: `Sen`（銭）の branded type を「検証済みの金額」に限定する

- ステータス: 🟡 部分採用（残課題あり）
- 日付: 2026-07-28
- 関連: T-048, `.claude/rules/backend.md`

## 背景

`type Sen = number` の別名では円と銭の取り違えを型が見逃す（T-048）。
`.claude/CLAUDE.md` は「値オブジェクトは branded type + ファクトリ関数で
不変条件を守る」と定めている。

## 決定

`Sen` を branded type にし、`createSen()` / `senFromYen()` を唯一の入口とする。
ただし**適用範囲を「検証を通った金額」に限定する**。

| 場所                                      | 型       | 理由                                                     |
| ----------------------------------------- | -------- | -------------------------------------------------------- |
| `createSen` / `senFromYen` の戻り値       | `Sen`    | ここが検証の出口                                         |
| 10指標の計算関数の**入力**                | `number` | **未検証の入力を受け取り、検証すること自体が責務**だから |
| `Company` / `DividendRecord` のフィールド | `number` | TSV/CSV 由来の未検証データだから                         |

未検証の値に `Sen` を付けると branding が「検証済み」を保証しなくなり、
**型が嘘をつく**。それは branded type を入れない状態より悪い。

## 理由

- 各指標の計算関数は既に `isSen()`（`NaN` / `Infinity` / 小数 / 安全整数外を弾く）で
  実行時検証しており、**検証の主体はここにある**
- 円↔銭の取り違えが実際に起きるのは入力の変換地点（フォームの `yenToSen`、
  `parsePriceInput`）であり、そこは `Sen` を通すよう設計できる

## 残課題（意図的に残している）

**集約（`Company`）まで branding が届いていない。**
取り込み層（F-02 / F-04 の CSV・TSV パーサー、Phase 2）が検証済みの値を作るように
なった時点で、`Company` のフィールドを `Sen` に上げる。そのとき
10指標の入力型も `Sen` に変えられる。

現状は「実行時には守られているが、型では守られていない」状態であることを
明示しておく。**守れているように書かない。**
