## 2. 個別の修正理由

### 2.1 🔴 `Score` — 「1〜10の整数」→「0〜10の整数。判定不能は `null`」

**現行の記述が実装・仕様の両方と食い違っている。**

- `docs/01_requirements/scoring-requirements.md` §0.3: 「③⑤⑥⑨⑩ とも値が負なら **0点**」
- 同 §0.4: 「③ の無配は **0点**」
- 同 §0.5: 「計算不能な指標は **0点として合算**」「個別指標の表示は `—`（判定不能）」
- 実装 `src/lib/scoring/dividend-yield.ts:75-87`: `DIVIDEND_YIELD_BANDS` は
  **0点の区分を含む11要素**
- 実装 `src/lib/scoring/dividend-yield.ts:61`: `score: number | null`

用語集どおり「1〜10」でファクトリを書くと、**0点が作れずスコアリングが成立しない。**

### 2.2 🔴 `ScoreThreshold` — 「10段階／境界値9個」→「11段階／境界値10個」

0点から10点まで = **11段階**。段階の境界は **10個**。
また「閾値以上で次の段階（`>=`判定）」という表現は、`scoring-requirements.md` §0.1 の
**「下限以上・上限未満」**（最上位のみ上が開く）と揃える必要がある。
実装は `ScoreBand { minInclusive, maxExclusive, points }` の配列でこれを表現している
（`src/lib/scoring/score-table.ts:11-18`）。

### 2.3 🟡 `UserScoringPolicy` / `DefaultThreshold` / `MasterUser` / `Viewer` — 未決の明示

用語集はこの4語を断定形で定義しているが、**前提となる認証が未決**:

- `docs/03_tasks/todo-list.md` T-003「認証の要否を決める（単一ユーザーなら不要）」🔴
- `docs/03_tasks/current-sprint.md`「『自分だけがローカルで使う』なら認証は不要」

単一ユーザーに決まれば `MasterUser` / `Viewer` / `UserScoringPolicy` は**不要になる**。
決着まで **コードで使わない語として凍結**し、その旨を用語集に書く。

### 2.4 🟡 `CAGR` — 指標ごとに始値・終値の定義が違う

現行の「(終値/始値)^(1/年数)-1」は ①⑦ には正しいが、**④ EPS は中央値ベース**:

> 一過性の特別損益をならすため、**直近3年の中央値**と**5年前から遡った3年の中央値**を使って
> 成長率を算出する（`docs/02_design/logic/eps-cagr-scoring.md:32`）

旧実装は④も端点で計算していた（`reference/legacy-web/app.js:216-227`）。
用語集が端点式だけを書いていると、**旧実装と同じ誤りを新規実装で繰り返す。**

### 2.5 🟡 `ScoringService` — 総合点と有効指標数もここ

旧実装は総合点の合算を**カード描画関数の中**でやっていた
（`reference/legacy-web/app.js:645-656`）。同じことを繰り返さないよう、
総合点（`TotalScore`）と有効指標数（`EffectiveMetricCount`）の算出責務を
用語集の時点で `ScoringService` に固定しておく。

### 2.6 🟢 追加10語

いずれも**すでに実装に存在する**か、`scoring-requirements.md` §0.5 が要求している概念。
用語集に無いまま9指標を書くと、指標ごとに別名が生える。

| 整形指標     | TransformedMetric  | エンティティ   | 財務レコードから計算された指標（CAGR・平均等）。計算時点の値                                       |

| スコアリング   | ScoringService       | ドメインサービス | 整形指標×閾値→全指標のスコアを算出する。**総合点と有効指標数の算出もここに置く**（表示層で合算しない）                                                               |
