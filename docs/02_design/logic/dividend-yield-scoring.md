# 配当利回りスコアリング 仕様書（指標⑩）

> 出典: OneDrive「銘柄スカウティング」`docs/specs/dividend_yield_scoring_spec.md`（2026-07-26 取り込み）
> 取り込み時に、プロジェクト規約（`CLAUDE.md`）と矛盾する3点を修正した。§6 に差分を記載。

## 1. 概要

銘柄の「現在の株価」と「年間配当金」から配当利回りを算出し、スコアリングを行う機能を定義する。
スコア表の原典は [scoring-requirements.md](../../01_requirements/scoring-requirements.md) の指標⑩。

## 2. 業務ロジック

### 2.1. データ取得

- **現在の株価**: ユーザーが「データ入力・解析タブ」の専用入力フィールドに手動入力した値
- **年間配当金**:
  1. 解析された配当履歴データの中から、最新の「予想（または修正）」値を優先して取得する
  2. 「予想」データが存在しない場合は、最新の「実績」値を取得する

> 予想値を採用したか実績値を採用したかを結果に保持し、UI に表示すること
> （予想と実績は区別する — `CLAUDE.md` の規約）。

### 2.2. 計算式

$$\text{配当利回り (\%)} = \left( \frac{\text{年間配当金}}{\text{現在の株価}} \right) \times 100$$

**丸めの扱い（原典から変更）:**

- **判定（スコア算出）には丸めていない値を使う**
- **表示のみ** 小数点第3位を四捨五入し、第2位まで表示する

原典は「第2位までを表示・判定に使用する」としていたが、判定に丸め値を使うと
境界でスコアが変わる。例: 実際の利回り 5.4951% は、丸めると 5.50% となり
10点（5.50%以上）、丸めなければ 9点（5.25%〜5.50%未満）。
プロジェクト規約「表示直前まで丸めない」に従い、判定は生値で行う。

### 2.3. スコアリング判定

[scoring-requirements.md](../../01_requirements/scoring-requirements.md) の指標⑩に基づく。
区分の解釈は **「下限以上、上限未満」**（同§0.1 の規約）。

| 利回り（下限） | 利回り（上限） | 点数 |
| :------------- | :------------- | :--- |
| 5.50%          | 以上           | 10   |
| 5.25%          | 5.50%          | 9    |
| 5.00%          | 5.25%          | 8    |
| 4.75%          | 5.00%          | 7    |
| 4.50%          | 4.75%          | 6    |
| 4.25%          | 4.50%          | 5    |
| 4.00%          | 4.25%          | 4    |
| 3.75%          | 4.00%          | 3    |
| 3.50%          | 3.75%          | 2    |
| 3.25%          | 3.50%          | 1    |
| 0.00%          | 3.25%          | 0    |

## 3. UI / UX 要件

### 3.1. データ入力・解析タブ

- **株価入力フィールド**
  - 左カラム（CSV エリア）または上部に「現在株価（円）」の入力欄を配置
  - 数値のみ入力可能。初期値は空
  - 全角数字は半角に正規化する（日本語環境では日常的に混入する）
- **実行トリガー**
  - 既存の「解析する」ボタン押下時に、CSV/TSV のパース処理と合わせて利回り計算を実行
- **結果表示**
  - スコア一覧に「配当利回り」の項目を追加し、算出された利回り（%）と点数を表示
  - 採用した配当が「予想」か「実績」かを併記する

### 3.2. 評価基準タブ

- 「配当利回り」カードのステータスを「未実装」から「自動計算済」に変更する
  （[criteria-tab.md](../ui/pages/criteria-tab.md) 参照）

## 4. 例外処理

> **原典から変更あり。** 「計算できなかった」と「計算した結果が最低点」を区別する
> （`CLAUDE.md`「無配とデータ欠損を区別する」規約）。

| 状況                  | 利回り                   | スコア                 | 画面表示                         |
| :-------------------- | :----------------------- | :--------------------- | :------------------------------- |
| 株価が未入力          | 計算しない               | **`null`（判定不能）** | `—` ＋「株価を入力してください」 |
| 株価が 0              | 計算しない（ゼロ除算）   | **`null`（判定不能）** | `—` ＋「株価が 0 です」          |
| 株価が負              | 計算しない（入力エラー） | **`null`（判定不能）** | `—` ＋「株価が不正です」         |
| 配当データが1件もない | 計算しない               | **`null`（判定不能）** | `—` ＋「配当データがありません」 |
| 配当額が 0（無配）    | 0.00%                    | **0点**                | `0.00%` / 0点                    |

**`null`（判定不能）と 0点は別物として扱うこと。**

> ただし **総合点の集計時は `null` を 0点として合算する**
> （[scoring-requirements.md §0.5](../../01_requirements/scoring-requirements.md) の決定。
> 分母は常に 100点）。区別が要るのは**画面表示**で、`null` は `0.00%` / `0点` ではなく
> `—` と出すこと。総合点の隣には有効指標数を併記する。
> 総合点の算出時に `null` を 0点として合算すると、データが揃っていない銘柄が
> 不当に低く評価される。合計点には有効指標数を併記する。

## 5. テスト観点

実装時に最低限これらを網羅すること。

- [ ] 境界値ちょうど: 5.50% → 10点、5.4999...% → 9点、3.25% → 1点、3.2499...% → 0点
- [ ] 丸めの影響: 5.4951%（表示 5.50%）が **9点**になること（10点にならないこと）
- [ ] 株価 0 → `null`（0点ではない）
- [ ] 配当データなし → `null`（0点ではない）
- [ ] 無配（配当 0 円、株価あり）→ 0.00% / **0点**（`null` ではない）
- [ ] 予想値と実績値の両方がある → 予想値を採用
- [ ] 実績値のみ → 実績値を採用し、その旨を表示
- [ ] 全角数字での株価入力 → 半角に正規化されて計算される

## 6. 原典からの変更点

| #   | 原典の記述                                                  | 変更後                   | 理由                                                    |
| :-- | :---------------------------------------------------------- | :----------------------- | :------------------------------------------------------ |
| 1   | 「第2位までを表示・**判定**に使用」                         | 判定は生値、表示のみ丸め | 丸めると境界でスコアが変わる（§2.2）                    |
| 2   | 株価未入力/0 → 「スコアは『0』**または**『判定不能（-）』」 | `null`（判定不能）に確定 | 二択のまま実装できない。かつ欠損を 0 にしない規約に従う |
| 3   | 配当データなし → 「スコアを『0』として扱う」                | `null`（判定不能）       | 同上。データ欠損を 0点にすると比較が歪む                |

いずれも `CLAUDE.md` のプロジェクト規約に合わせた変更。
**投資方針そのものを変える変更（閾値の増減など）は行っていない。**

## 7. 既存実装との対応

前身の実装が [reference/legacy-web/](../../../reference/legacy-web/README.md) にある
（`getDividendYieldScore()`）。本仕様との関係は次のとおり。

| 本仕様                                     | 既存実装                                                         | 判定                                        |
| :----------------------------------------- | :--------------------------------------------------------------- | :------------------------------------------ |
| 判定は生値、表示のみ丸め（§2.2）           | 生値で比較している                                               | ✅ **一致。** 上の変更1が正しいことの裏付け |
| 境界は「下限以上、上限未満」（§2.3）       | `pct >= 5.50` 形式                                               | ✅ 一致                                     |
| 株価未入力・0 → `null`（§4）               | **0点**を返す                                                    | ❌ **不一致。** 新規実装は本仕様に従う      |
| 配当データなし → `null`（§4）              | **0点**を返す                                                    | ❌ 同上                                     |
| 予想／実績のどちらを採用したか表示（§3.1） | 内部では予想を優先しているが、**採用元を保持も表示もしていない** | ❌ 新規実装で対応                           |

旧実装は全スコアを `0` で初期化しており、「計算不能」を表現できない。
新規実装では最初から `null` を返せる型にすること。
