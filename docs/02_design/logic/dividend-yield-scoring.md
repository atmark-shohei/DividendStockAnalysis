# 配当利回りスコアリング 仕様書（指標⑩）

> 出典: OneDrive「銘柄スカウティング」`docs/specs/dividend_yield_scoring_spec.md`（2026-07-26 取り込み）
> 取り込み時に、プロジェクト規約（`CLAUDE.md`）と矛盾する3点を修正した。§6 に差分を記載。

## 1. 概要

銘柄の「現在の株価」と「年間配当金」から配当利回りを算出し、スコアリングを行う機能を定義する。
スコア表の原典は [scoring-requirements.md](../../01_requirements/scoring-requirements.md) の指標⑩。

## 2. 業務ロジック

### 2.1. データ取得

- **現在の株価**: ユーザーが「データ入力・解析タブ」の専用入力フィールドに手動入力した値
- **株価の上限**: 1株 **1,000,000 円**。これを超える入力は桁の打ち間違いとみなして弾く
  （§4 の `price-too-large`）。画面の入力欄も同じ値で範囲検証する
- **年間配当金**:
  1. 取り込んだ配当履歴データの**最新年度**に「予想（または修正）」があれば、それを採用する
  2. **最新年度に「予想」が無い場合のみ**、最新の「実績」値を採用する
  3. 同一年度に「予想」と「修正」が並ぶ場合は「修正」を採用する（修正は予想の更新版）

> 予想値を採用したか実績値を採用したかを結果に保持し、UI に表示すること
> （予想と実績は区別する — `CLAUDE.md` の規約）。

> **年度を見る理由（2026-07-27 決定。T-049 クローズ）**
>
> 「予想があれば優先」を年度を見ずに実装すると、**予想が1件でもあれば年度に関係なく
> それを採用し、より新しい実績を無視する。** FY2019 の予想と FY2024 の実績が
> 混在した CSV では、5年前の予想で利回りが計算され、画面には「予想」とだけ出るので
> いつ時点の値か分からない。`CLAUDE.md`「古いデータを最新として表示しない」に反する。
>
> 上の 1. / 2. は「最新年度」を基準にすることでこれを避ける。
> 年度が壊れている（`NaN` 等）レコードは、最新年度の判定ごと壊すので採用対象から外す。

### 2.2. 計算式

$$\text{配当利回り (\%)} = \left( \frac{\text{年間配当金}}{\text{現在の株価}} \right) \times 100$$

**丸めの扱い（原典から変更）:**

- **判定（スコア算出）には丸めていない値を使う**
- **表示のみ** 小数点第3位を四捨五入し、第2位まで表示する

原典は「第2位までを表示・判定に使用する」としていたが、判定に丸め値を使うと
境界でスコアが変わる。例: 実際の利回り 5.4951% は、丸めると 5.50% となり
10点（5.50%以上）、丸めなければ 9点（5.25%〜5.50%未満）。
プロジェクト規約「表示直前まで丸めない」に従い、判定は生値で行う。

### 2.3. スコアリング判定

[scoring-requirements.md](../../01_requirements/scoring-requirements.md) の指標⑩に基づく。
区分の解釈は **「下限以上、上限未満」**（同§0.1 の規約）。

| 利回り（下限） | 利回り（上限） | 点数 |
| :------------- | :------------- | :--- |
| 5.50%          | 以上           | 10   |
| 5.25%          | 5.50%          | 9    |
| 5.00%          | 5.25%          | 8    |
| 4.75%          | 5.00%          | 7    |
| 4.50%          | 4.75%          | 6    |
| 4.25%          | 4.50%          | 5    |
| 4.00%          | 4.25%          | 4    |
| 3.75%          | 4.00%          | 3    |
| 3.50%          | 3.75%          | 2    |
| 3.25%          | 3.50%          | 1    |
| 0.00%          | 3.25%          | 0    |

## 3. UI / UX 要件

### 3.1. データ入力・解析タブ

- **株価入力フィールド**
  - 左カラム（CSV エリア）または上部に「現在株価（円）」の入力欄を配置
  - 数値のみ入力可能。初期値は空
  - 全角数字は半角に正規化する（日本語環境では日常的に混入する）
- **実行トリガー**
  - 既存の「解析する」ボタン押下時に、CSV/TSV のパース処理と合わせて利回り計算を実行
- **結果表示**
  - スコア一覧に「配当利回り」の項目を追加し、算出された利回り（%）と点数を表示
  - 採用した配当が「予想」か「実績」かを併記する

### 3.2. 評価基準タブ

- 「配当利回り」カードのステータスを「未実装」から「自動計算済」に変更する
  （[criteria-tab.md](../ui/pages/criteria-tab.md) 参照）

> **2026-07-27 解消。** 以前は criteria-tab.md に「配当利回り」カードの記載が
> そもそも無く、この節が指す対象が存在しなかった。同設計書に §2.1
> 「カード一覧と実装状態」を追加し、⑩ を **自動計算済**として載せた。
>

## 4. 例外処理

> **原典から変更あり。** 「計算できなかった」と「計算した結果が最低点」を区別する
> （`CLAUDE.md`「無配とデータ欠損を区別する」規約）。

| 状況                       | 理由コード         | スコア                 | 画面表示                           |
| :------------------------- | :----------------- | :--------------------- | :--------------------------------- |
| 株価が未入力               | `price-missing`    | **`null`（判定不能）** | `—` ＋「株価を入力してください」   |
| 株価が 0                   | `price-zero`       | **`null`（判定不能）** | `—` ＋「株価が 0 です」            |
| 株価が負                   | `price-negative`   | **`null`（判定不能）** | `—` ＋「株価が不正です」           |
| 株価が 100万円 超          | `price-too-large`  | **`null`（判定不能）** | `—` ＋「株価が上限を超えています」 |
| 株価が数値として壊れている | `price-invalid`    | **`null`（判定不能）** | `—` ＋「株価が不正です」           |
| 配当データが1件もない      | `dividend-missing` | **`null`（判定不能）** | `—` ＋「配当データがありません」   |
| 配当額が壊れている         | `dividend-invalid` | **`null`（判定不能）** | `—` ＋「配当データが不正です」     |
| 配当額が 0（無配）         | （なし）           | **0点**                | `0.00%` / 0点                      |
| 配当額が負                 | （なし）           | **0点**                | `0.00%` / 0点（無配と同じ）        |

> **理由コードは `YieldUnavailableReason` と 1 対 1 で対応する。**
> 「株価が 0」と「株価が負」を1つのコードにまとめると、画面が別のメッセージを
> 出せなくなる。実装時に一度まとめてしまい、レビューで検出した。
>
> `price-too-large` / `price-invalid` / `dividend-invalid` は原典に無い。
> §6 の変更点4・6 を参照。
>
> 「壊れている」は **`NaN` / `Infinity` / 小数 / 安全整数の範囲外**。
> `price-too-large` はそれとは別で、**業務上の上限（1株 100万円）超**を指す。
> 桁の打ち間違いは「不正な値」ではなく「大きすぎる値」なので、
> 画面に出すメッセージを分けられるよう理由コードも分けている。
>
> 配当額の上限は約 90億円で、これは判定式 `配当 * 10000` が安全整数に収まる範囲から
> 導出している（業務上の上限ではない）。株価側は業務上限が算術上の安全域より
> はるかに小さいので、業務上限だけを見れば足りる。

**`null`（判定不能）と 0点は別物として扱うこと。**

> ただし **総合点の集計時は `null` を 0点として合算する**
> （[scoring-requirements.md §0.5](../../01_requirements/scoring-requirements.md) の決定。
> 分母は常に 100点）。区別が要るのは**画面表示**で、`null` は `0.00%` / `0点` ではなく
> `—` と出すこと。総合点の隣には有効指標数を併記する。
> 総合点の算出時に `null` を 0点として合算すると、データが揃っていない銘柄が
> 不当に低く評価される。合計点には有効指標数を併記する。

## 6. 原典からの変更点

| #   | 原典の記述                                                  | 変更後                   | 理由                                                    |
| :-- | :---------------------------------------------------------- | :----------------------- | :------------------------------------------------------ |
| 1   | 「第2位までを表示・**判定**に使用」                         | 判定は生値、表示のみ丸め | 丸めると境界でスコアが変わる（§2.2）                    |
| 2   | 株価未入力/0 → 「スコアは『0』**または**『判定不能（-）』」 | `null`（判定不能）に確定 | 二択のまま実装できない。かつ欠損を 0 にしない規約に従う |
| 3   | 配当データなし → 「スコアを『0』として扱う」                | `null`（判定不能）       | 同上。データ欠損を 0点にすると比較が歪む                |
| 4   | 壊れた数値（NaN 等）の規定なし                              | `null`（判定不能）       | 下記                                                    |
| 5   | 配当額が負の規定なし                                        | **0点（無配と同じ）**    | 下記                                                    |
| 6   | 株価の上限の規定なし                                        | 1株 100万円 超は判定不能 | 下記                                                    |

**変更点4 について（2026-07-27 実装時に追加）**

原典は「株価が数値として壊れている」場合を規定していない。
規定が無いまま素朴に実装すると、**`NaN` が全ガードを素通りして最高点の 10点を返した**
（`NaN < 0` も `NaN >= 0` も false になるため）。破損データの銘柄が最上位に浮上する。

`.claude/rules/backend.md`「外部データは常に壊れている前提で扱う」に従い、
`Number.isSafeInteger` を通らない入力は判定不能に倒す。

**オペランドの検証だけでは足りない。** 判定式は `配当 * 10000` と `閾値 * 株価` を
計算するので、入力が安全整数でも**積**が範囲を外れて比較が逆転する
（実測: 株価 9007199254740991 銭で 5.25% の判定が 9点、厳密には 8点）。
配当側は積から上限を導出して弾き、株価側は変更点6 の業務上限がそれより厳しいので
そちらで足りている。両側が縛られてはじめて「除算なしで厳密に比較できる」が成立する。

**変更点5 について（2026-07-27 決定）**

原典は「配当額が負」の場合を規定していない。**制度上、配当額が負になることはない。**
データの都合で負が入ってきたときは、無配（0円）と同じ **0点**として扱う。

実装時にはいったん「0点にすると無配と区別できなくなる」として判定不能に倒していたが、
これは `scoring-requirements.md` §0.3「負の値は 0点（③⑤⑥⑨）」と逆向きだった。
⑩ も同じ原則に揃える。表示利回りも負にせず `0.00%` と出す
（`-5.00%` と出ると、利回りが計算できたように見えてしまう）。

なお「負の配当が入っていた」という事実そのものは、スコアリング層ではなく
**取り込み層で記録する**（`.claude/rules/backend.md`「検証に落ちたデータは捨てずに記録」）。
純粋関数であるこの層は、判定結果だけを返す。

**変更点6 について（2026-07-27 決定）**

原典は株価の上限を規定していない。**1株 1,000,000 円**を上限とし、
超える入力は桁の打ち間違いとみなして `price-too-large` で弾く。
「壊れている」（`price-invalid`）とは別の理由コードにしてあるのは、
画面に出すメッセージが違うため（§4 の1対1原則）。

副次的な効果として、株価側の積のオーバーフローを考える必要がなくなる。
`閾値 * 株価` は最大でも `550 * 1e8 = 5.5e10` で、安全整数の範囲に十分収まる。

いずれも `CLAUDE.md` のプロジェクト規約に合わせた変更。
**投資方針そのものを変える変更（閾値の増減など）は行っていない。**

## 7. 既存実装との対応

前身の実装が [reference/legacy-web/](../../../reference/legacy-web/README.md) にある
（`getDividendYieldScore()`）。本仕様との関係は次のとおり。

| 本仕様                                     | 既存実装                                                         | 判定                                        |
| :----------------------------------------- | :--------------------------------------------------------------- | :------------------------------------------ |
| 判定は生値、表示のみ丸め（§2.2）           | 生値で比較している                                               | ✅ **一致。** 上の変更1が正しいことの裏付け |
| 境界は「下限以上、上限未満」（§2.3）       | `pct >= 5.50` 形式                                               | ✅ 一致                                     |
| 株価未入力・0 → `null`（§4）               | **0点**を返す                                                    | ❌ **不一致。** 新規実装は本仕様に従う      |
| 配当データなし → `null`（§4）              | **0点**を返す                                                    | ❌ 同上                                     |
| 予想／実績のどちらを採用したか表示（§3.1） | 内部では予想を優先しているが、**採用元を保持も表示もしていない** | ❌ 新規実装で対応                           |

旧実装は全スコアを `0` で初期化しており、「計算不能」を表現できない。
新規実装では最初から `null` を返せる型にすること。

## 8. 参考資料との差分

参考資料 `high_dividend_10_indicators_scoring.md`（YouTube「高配当ラボ」由来）の
**⑩ 配当利回り** に相当する。

10点〜2点（5.5%以上〜3.5〜3.75%）まで**完全一致**。

| 項目      | 本仕様（SSoT） | 参考資料       |
| :-------- | :------------- | :------------- |
| 1点の区間 | 3.25%〜3.50%   | **3.0%〜3.5%** |
| 0点       | 0%〜3.25%      | **3.0%未満**   |

**影響:**

配当利回り 3.0〜3.25% の銘柄が、本仕様では 0点、参考資料では 1点になる。
相違は1行のみで、10指標のなかでは最も小さい。

### 決定（2026-07-27）

✅ **正典据え置き。** 参考資料の `3.0%〜3.5% → 1点` は採らず、
`3.25%〜3.50% → 1点` を維持する。①④⑤⑦⑧ と同じく、参考資料のほうが緩い方向の
相違であり、辛い側を既定とする方針に従う。

判断の全体像は
[scoring-source-comparison.md](../../01_requirements/scoring-source-comparison.md) にある。
