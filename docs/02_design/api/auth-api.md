### エンドポイント

#### POST /api/auth/login

リクエスト:
```json
{ "email": "user@example.com", "password": "..." }
```

レスポンス（200）:
```json
{ "user": { "id": 1, "email": "user@example.com" } }
```

エラー:

| ステータス | 条件 | 応答 |
|---|---|---|
| 400 | 入力形式不正 | `{ "error": "invalid_request" }` |
| 401 | 認証失敗 | `{ "error": "invalid_credentials" }` |
| 429 | 試行回数超過 | `{ "error": "too_many_attempts" }` |

> ⚠️ **「メールアドレスが存在しない」と「パスワードが違う」を区別して返さない。**
> アカウントの存在を漏らす。

#### POST /api/auth/logout

セッションを破棄する。常に 204 を返す。

#### GET /api/auth/me

現在のユーザーを返す。未認証なら 401。

### セキュリティ要件

- パスワードは bcrypt / argon2 でハッシュ化する。**平文・可逆暗号で保存しない**
- セッションクッキーは `HttpOnly` `Secure` `SameSite=Lax`
- ログイン試行にレート制限をかける
- エラー応答に内部情報（SQL・スタックトレース）を含めない
- パスワード・トークンをログに出さない
