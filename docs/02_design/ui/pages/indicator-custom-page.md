## 1. 概要

**ログイン必須**（user・admin ロール）。ユーザーが10指標のうち 5〜10 個を選び、
指標ごとに「満点（10点）となる基準値」を設定できる画面。

- 選択・基準値は**ユーザーに紐づく永続設定**であり、銘柄ごとではない
  （1ユーザーにつき1組の設定。試作にも複数プロファイルの概念は無い）
- MIX係数（⑨）だけは基準値を設定できない（`bands.ts` の定数を常に使う派生指標）。
  選択・除外は他の指標と同様にできる
- **URL には置かない。** 選択画面の表示状態（どの指標が選ばれているか、基準値の
  入力途中の値）は共有・直リンクする対象ではなく、`.claude/rules/frontend.md`
  「URLに置けるもの」（表示中の画面・選択中の銘柄コードのような**ナビゲーション状態**）
  には当たらない。保存済みの設定は API から取得するサーバーデータであり、
  `frontend/rules` の「サーバーデータをクライアント state にコピーしない」原則の
  対象にもならない（フォームの編集中値は一時的にコピーせざるを得ないが、
  保存後は再取得して真実の情報源をサーバーに保つ）

## 2. レイアウト

試作（[design_mock/README.md](../../../design_mock/README.md) §5）のレイアウトを採用する。

```
┌──────────────────────────────────────────┐
│ 選択中 X / 10（最小 5）  [警告バナー: X<5のとき] │
│ ※ 指標の選択・基準値が異なる相手とは総合点を    │
│   単純比較できません                          │
├──────────────────────────────────────────┤
│ [トグル] 増配率（5年CAGR）                    │
│          0.1%きざみ・0%〜50%                 │
│          [満点となる基準値: __.__ %]         │
├──────────────────────────────────────────┤
│ ...（10指標ぶん、§3 の順で）                  │
├──────────────────────────────────────────┤
│ [トグル] MIX係数                             │
│          配当利回り・増配率から自動算出（chip） │
├──────────────────────────────────────────┤
│ [設定を保存]（塗り）  [初期設定に戻す]（枠線）  │
└──────────────────────────────────────────┘
```

- ヘッダのカウンタ「選択中 X / 10（最小 5）」は常時表示。**X < 5 のとき amber
  （`--color-caution`）に変わり、警告バナーが出る**
  （[design-tokens.md](../design-tokens.md) §2.2。選択数の制約は注意であって
  エラーではないため `--color-caution` を使う。§2.3 のエラー統合ルールとは別の用途）
- 1指標＝1行。トグル（22×22px 角丸スクエア、選択時 `--color-action`）＋指標名＋
  制約キャプション（きざみ・下限・上限。§3 の表からそのまま出す）＋数値入力
  （`type="number"`、`step`/`min`/`max` は §3 の表の値をそのまま使う）
- **選択解除された行の数値入力は disabled にするが、入力値自体は保持する**
  （再度選択したときに前回値へ戻す。ゼロクリアしない）
- MIX係数の行だけ数値入力の代わりに「配当利回り・増配率から自動算出」の
  静的チップを表示する（試作どおり。§4 の理由により設定不可）
- **「総合点は比較不能」の注記は常時表示する（省略しない）。**
  [ADR-0012](../../../adr/0012-indicator-customization-scaling-and-denominator.md)
  §決定D-3 が「画面（指標カスタマイズ・解析ダイアログ）に必ず明記すること」と
  定めている（2026-08-17、T-088レビューで本画面への反映漏れが発覚し追加）

## 3. 指標ごとの制約（試作の制約表を踏襲）

| 指標                | きざみ                 | 下限 | 上限 | 単位 | 区分表の向き（`bands.ts`） |
| :------------------ | :--------------------- | :--- | :--- | :--- | :------------------------- |
| 増配率（5年CAGR）   | 0.1                    | 0    | 50   | %    | 昇順                       |
| 連続非減配年数      | 1                      | 0    | 50   | 年   | 昇順                       |
| 予想配当性向        | 1                      | −100 | 500  | %    | **降順**（§4 参照）        |
| EPSの5年CAGR        | 0.1                    | 0    | 50   | %    | 昇順                       |
| ROEの5年平均        | 0.1                    | 0    | 100  | %    | 昇順                       |
| 配当維持可能年数    | 1                      | −100 | 100  | 年   | 昇順                       |
| 売上高の5年CAGR     | 1                      | 0    | 100  | %    | 昇順                       |
| 営業利益率の5年平均 | 0.1                    | 0    | 50   | %    | 昇順                       |
| MIX係数             | —（設定不可・derived） |      |      |      |
| 配当利回り          | 0.1                    | 0    | 50   | %    | 昇順                       |

きざみ・下限・上限は試作の値をそのまま採用した（要件メモ
[今後やりたいこと.md](../../../adr/今後やりたいこと.md) の記載とも一致）。
**UIの `min` 表示はこの表のまま変更しない。** ただし §4 のとおり、
保存時のドメイン検証はこの表の `min` より厳しくなる指標が2つある。

## 4. ⚠️ 基準値の追加ガード（ADR-0012）

**満点となる基準値は、常に正の数でなければならない。** [ADR-0012](../../../adr/0012-indicator-customization-scaling-and-denominator.md)
の比例スケーリングは `新境界 = デフォルト境界 × (基準値 ÷ デフォルト満点境界)` という式で
全境界を導出するため、基準値が0以下だと `scale ≤ 0` になり区分表そのものが崩壊する
（境界が全て0に潰れる、または大小関係が反転する）。

### 4.0 ③予想配当性向は基準値の意味が他の9指標と逆（2026-08-17 追加）

**「満点となる基準値」というラベルは全指標共通だが、意味が指標の向きで変わる。**
T-088レビューで、この違いが画面のどこにも説明されておらず誤読の危険があると指摘された。

| 向き                         | 対象指標          | 基準値に入れた値の意味                       |
| :--------------------------- | :---------------- | :------------------------------------------- |
| 昇順（値が大きいほど高得点） | ①②④⑤⑥⑦⑧⑩ の9指標  | 「**この値以上**で満点」（最上位区分の下限） |
| 降順（値が小さいほど高得点） | ③予想配当性向のみ | 「**この値未満**で満点」（最上位区分の上限） |

- **③の行には、他の指標と区別できる注記を必ず表示する。** 例:
  「配当性向はこの値**未満**で満点になります（他の指標と逆向きです）」を
  制約キャプションの下に追加する（§2 レイアウト）
- ③は10段で1点を返す経路が無い（[criteria-tab.md](./criteria-tab.md) の受入基準と同じ事実。
  正典の区分表がそう定義されているため、基準値をどう設定してもこの構造は変わらない）。
  この事実も③の行の注記に含める

- **③ 予想配当性向・⑥ 配当維持可能年数の2指標は、§3 の表の `min`（−100）が
  この制約と矛盾する。** UIの数値入力の `min` 属性は試作どおり −100 のまま残すが、
  **保存時（フロント送信前のバリデーション＋バックエンドのドメイン検証の両方）で
  「基準値 > 0」を追加でチェックし、満たさなければ保存を拒否する。**
- エラー文言例: 「満点となる基準値は 0 より大きい値にしてください」
  （`role="alert"`、該当行の入力欄近くに表示。トースト等の別UIを新設しない）
- ③（降順の区分表）でも同じ式が成立することは ADR-0012 §文脈で確認済み
  （単調減少であり、原典のような U字型ではないため）

## 5. 操作

| 操作                                    | 挙動                                                                                                                                    |
| :-------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------- |
| トグルを押して選択を増やす（現在 < 10） | 選択に追加。カウンタが増える                                                                                                            |
| トグルを押して選択を増やす（現在 = 10） | **no-op。** 上限に達しているため何も起きない（ブロックダイアログを出さない）                                                            |
| トグルを押して選択を減らす（現在 > 5）  | 選択を解除。カウンタが減る                                                                                                              |
| トグルを押して選択を減らす（現在 = 5）  | **no-op。** 下限を下回れない                                                                                                            |
| 「満点となる基準値」を編集              | ローカル state を更新。まだ保存しない                                                                                                   |
| 「設定を保存」                          | 選択中の指標ぶんの基準値をまとめて送信。§4 の検証に落ちた行があれば該当行にエラーを表示し、送信自体を行わない（一部だけ保存しない）     |
| 「初期設定に戻す」                      | 全指標を選択・デフォルト基準値（`bands.ts` 由来の値）に即時反映する（保存はまだされない。「設定を保存」を押すまでサーバーへは届かない） |

選択のブロックは**トグル操作そのものを no-op にする**（試作どおり）。
「5〜10個選んでください」のようなブロッキングモーダル/アラートは出さない。
永続的なカウンタと条件付き警告バナー（§2）だけで制約を伝える。

## 6. API

ユーザー指標設定の永続化 API は、ポートフォリオ API と合わせて
[portfolio-api.md](../../api/portfolio-api.md) §指標カスタマイズ が正（T-083 で確定）。
本ページが必要とする形だけここに再掲する。

- 取得: ユーザーの現在の選択指標・基準値一覧（未設定なら全10指標選択・デフォルト基準値相当を返す）
- 保存: 選択指標のキー一覧 ＋ 指標ごとの基準値のマップ。**選択していない指標の基準値は
  送らない**（サーバー側は「選択されなかった指標」と「基準値が未指定」を区別する必要がない
  設計にする）
- サーバー側は保存前に §4 の「基準値 > 0」と `validateBands()` 相当の検証を行う
  （フロントのバリデーションだけに頼らない。`.claude/rules/backend.md`）

## 7. エラー・空状態

| 状況                                       | 表示                                                                      |
| :----------------------------------------- | :------------------------------------------------------------------------ |
| 基準値が0以下（§4）                        | 該当行にエラー文言。保存を中断                                            |
| 基準値が §3 の `min`/`max` の範囲外        | 該当行にエラー文言（`aria-invalid="true"`。`NumberInput` の既存パターン） |
| 保存に失敗（ネットワーク・サーバーエラー） | `role="alert"` でエラーを表示。入力内容は失わない                         |
| 初回アクセス（設定が未保存）               | 空状態ではなく、全10指標選択・デフォルト基準値を初期表示する（§6）        |

## 8. アクセシビリティ

- トグルは `<button role="button" aria-pressed>` またはネイティブ `<input type="checkbox">`。
  `div` + `onClick` にしない（`.claude/rules/frontend.md`）
- 数値入力は `<NumberInput>`（既存コンポーネント方針。全角数字の正規化・範囲検証込み）
- 選択数が5未満のときの警告バナーは `role="status"`（緊急のエラーではなく状態通知のため）

## 9. 受入基準

- ✅ 選択数が5〜10の範囲外になる操作（トグル）は no-op になり、カウンタが変化しない
- ✅ 選択数が5未満のとき、カウンタが amber になり警告バナーが表示される
- ✅ 「総合点は比較不能」の注記が画面を開くたびに常時表示される（非表示にできない）
- ✅ ③予想配当性向の行に、基準値が「この値未満で満点」であることを示す注記が表示される
  （他の9指標の「以上」と区別できる文言になっている）
- ✅ MIX係数の行に数値入力が無く、静的チップが表示される
- ✅ ③・⑥ に 0 以下の基準値を入力して保存すると、送信されずにエラーが表示される
- ✅ ①②④⑤⑦⑧⑩ に 0 以下の基準値を入力して保存すると、同様にエラーが表示される
  （§4 の制約は全昇順指標に共通。UIの `min` が0の指標でも、境界値の直接入力や
  IME/貼り付け経由で0以下が渡るケースをガードする）
- ✅ 「初期設定に戻す」を押すと全10指標が選択され、基準値が `bands.ts` のデフォルト
  満点境界に一致する
- ✅ 保存成功後に再取得した設定が、保存直前の編集内容と一致する
- ✅ 選択・基準値の状態が URL に一切反映されない（§1 の決定どおり）
- ✅ `frontend/` に色・サイズの直値が無い（[design-tokens.md](../design-tokens.md) §6）
