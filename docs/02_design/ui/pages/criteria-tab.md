## 1. 概要

[scoring-requirements.md](../../../01_requirements/scoring-requirements.md) で定義された
10個の指標の評価ロジックを、ユーザー向けに一覧表示して説明するタブ。

**ログイン不要で閲覧できる公開画面。** 採点根拠を隠さないことが
「推奨をしない分析ツール」という立場の裏付けになるため、認証の背後に置かない。

## 2. UI デザインと表示要素

### 2.0 レイアウト（2026-08-16 更新）

- **カードの2列グリッド。** 1指標＝1カード、10枚を ①〜⑩ の順に並べる
- カードの構成は上から順に:
  1. **指標名**（`--font-size-md` / 700）＋ 実装状態バッジ（§2.3）
  2. **1行の説明**（`--font-size-sm` / `--color-text-secondary`）
  3. **計算式**（等幅フォントのインセットブロック。背景 `--color-surface-inset`）
  4. **条件／点数の表**（`<table>`。条件列は左寄せ、点数列は右寄せ＋等幅）
- カード: 背景 `--color-surface`、枠線 `--color-line`、角丸 `--radius-lg`
- 色は [design-tokens.md](../design-tokens.md) のトークンだけを使う。直値を書かない

画面のバッジはここからではなく**スコアリングエンジンが返す実装済み指標の一覧**から
描画する（§3 参照）。表とバッジが二重管理になるのを避けるため、
実装が進んだらこの表も更新するが、正はあくまでエンジン側。

**⑩ のカードに固有の表示要件:**

- 採用した配当が**予想か実績か**を必ず併記する。どちらか分からない表示にしない
  （[dividend-yield-scoring.md](../../logic/dividend-yield-scoring.md) §2.1）
- 判定不能（`null`）は `0.00%` / `0点` ではなく `—` と理由メッセージを出す。
  理由コードごとにメッセージを出し分ける（同 §4 の表）
- 無配（0円）と判定不能を同じ見た目にしない

### 2.2 撤回した記述（2026-08-16）

| 旧記述                           | 撤回の理由                                                                                                             |
| :------------------------------- | :--------------------------------------------------------------------------------------------------------------------- |
| ガラスモーフィズムスタイル       | 試作は**フラットな面＋ヘアライン枠線**で統一しており、影・透過を使わない（[design-tokens.md](../design-tokens.md) §4） |
| 「自動計算済」バッジを**緑色**で | **緑・赤はポートフォリオの評価損益専用**（同 §2.2）。バッジに使うと色の役割が重複する                                  |

バッジの配色は「自動計算済」＝ `--color-text-secondary` の枠線バッジ、
「未実装」＝ `--color-caution`（注意の役割）とする。
**色だけで区別せず、必ず文言を出す。**

### 2.3 境界値の解釈を画面に明記する

各カードの表の下に「**各区分は下限以上・上限未満**（最上位のみ上が開く）」と常時表示する。
[scoring-requirements.md §0.1](../../../01_requirements/scoring-requirements.md) の規約であり、
これが無いとユーザーは「20% ちょうどは何点か」を判断できず、表の意味が無い。

### 2.4 ⚠️ 試作の数値・計算式は採用しない（2026-08-16 決定）

`design_mock/design-reference.html` の `criteria` 配列（702〜723行）は
**レイアウト確認用のダミー**であり、正典と**全10指標で食い違う**。

| 項目            | 試作                                      | 正典（こちらが正）                            |
| :-------------- | :---------------------------------------- | :-------------------------------------------- |
| 区分数          | 全指標4区分（10/7/4/0 点など）            | **11段（0〜10点）**。③ のみ10段               |
| ④ EPS CAGR の式 | `(最新EPS ÷ 5年前EPS)^(1/5) − 1`（端点）  | **中央値ベース**（`eps-cagr-scoring.md`）     |
| ⑨ MIX係数 の式  | 「配当利回り ＋ 増配率 の重み付き合成」   | **PER × PBR**（`mix-coefficient-scoring.md`） |
| ⑥ の式          | `(現金同等物＋5年FCF見込) ÷ 年間配当総額` | `balance-sheet-derivation.md` の導出          |

**試作から採るのはレイアウト・情報の並び・配色だけ。** 数値と式は §3 のとおり
`src/domain/scoring/bands.ts` と各指標の設計書から描画する。

## 3. 実装時の注意（2026-07-28 更新: 軽量DDD移行後のパス）

- **スコア表をこの画面にハードコードしない。** 表は
  [scoring-requirements.md](../../../01_requirements/scoring-requirements.md) が正であり、
  スコアリングエンジンと同一の定義（`src/domain/scoring/bands.ts` の10表。
  ~~旧: `src/lib/` の定数~~）から描画すること。
  画面とエンジンで表が二重管理になると、片方だけ直して不整合が起きる
- バッジの「自動計算済／未実装」も手書きせず、`src/domain/shared/metric-key.ts` の
  `METRIC_KEYS` を基準に、エンジンが返す `MetricScore` の有無から描画する形にする
  （2026-07-28 時点では10指標全て実装済みなので、バッジは全部「自動計算済」になる）
- 境界値の解釈（下限以上・上限未満）を画面上にも明記する。
  ユーザーが「20% ちょうどは何点か」を判断できないと表の意味がない

## 4. 受入基準（2026-08-16 追加）

- ✅ カードが10枚、①〜⑩ の順で表示される
- ✅ 表示される区分表の**行数と境界値が `src/domain/scoring/bands.ts` と完全に一致**する
  （③ は10段、他は11段。画面側に区分表のリテラルが存在しない）
- ✅ `bands.ts` の境界値を1つ変えると、テストを変えずに画面の表示も変わる（二重管理でない）
- ✅ 「各区分は下限以上・上限未満」の注記が全カードから読める位置にある（§2.3）
- ✅ ③ のカードに **1点の行が存在しない**（10段。意図的であることが読み取れる）
- ✅ ⑩ のカードに、採用した配当が予想か実績かの併記がある（§2.1 ⑩ 固有要件）
- ✅ 判定不能が `0.00%` / `0点` ではなく `—` ＋理由文言で出る
- ✅ ログインしていない状態で全内容が閲覧できる（§1）
- ✅ バッジが色だけでなく文言でも区別できる（§2.2）
- ✅ `frontend/` に色・サイズの直値が無い（[design-tokens.md](../design-tokens.md) §6）
