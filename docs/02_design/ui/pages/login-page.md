## 以下は「認証あり」と決まった場合の仕様

### レイアウト

```
┌────────────────────────────────┐
│                                │
│      DividendStockAnalysis     │
│                                │
│   ┌────────────────────────┐   │
│   │ メールアドレス            │   │
│   │ [                    ]  │   │
│   │                        │   │
│   │ パスワード               │   │
│   │ [                    ]  │   │
│   │                        │   │
│   │   [    ログイン    ]     │   │
│   └────────────────────────┘   │
│                                │
│   （エラー時のメッセージ表示領域）    │
│                                │
└────────────────────────────────┘
```

### 入力検証

| 項目           | クライアント側 | サーバー側                             |
| -------------- | -------------- | -------------------------------------- |
| メールアドレス | 形式チェック   | **必須**（クライアントだけに頼らない） |
| パスワード     | 空でないこと   | **必須**                               |

### エラー表示

| 状況           | 表示                                                     |
| -------------- | -------------------------------------------------------- |
| 認証失敗       | 「メールアドレスまたはパスワードが正しくありません」     |
| 試行回数超過   | 「しばらく時間をおいてからお試しください」               |
| サーバーエラー | 「ログインできませんでした。時間をおいてお試しください」 |

> ⚠️ **「そのメールアドレスは登録されていません」と出さない。**
> アカウントの存在有無が漏れる。認証失敗はすべて同じ文言にする。

### セキュリティ

- パスワードを `localStorage` / `sessionStorage` に保存しない
- 入力値をログ・エラー計測サービスに送らない
- 送信は POST のみ。GET のクエリに載せない
- ログイン成功後は元のページへ戻す。**リダイレクト先を外部 URL にしない**
  （オープンリダイレクト対策：相対パスのみ許可する）

### 受入基準

- ✅ 誤ったパスワードで、メールアドレスの存在有無が判別できない
- ✅ 連続失敗でレート制限が働く
- ✅ ログイン後、元のページに戻る
- ✅ `?redirect=https://evil.example.com` を渡しても外部に飛ばない
- ✅ パスワードがネットワークログ・アプリログに残らない
