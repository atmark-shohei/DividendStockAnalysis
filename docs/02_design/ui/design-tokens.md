## 1. 決定（D-5）

| 論点         | 決定                                                                           |
| :----------- | :----------------------------------------------------------------------------- |
| パレット     | **試作のパレットを採用する**（§2）                                             |
| フォント     | **システムフォント＋等幅フォールバック**。Web フォントは読み込まない（§4）     |
| スタイル手法 | **素の CSS ＋ カスタムプロパティを継続。** Tailwind / CSS Modules は導入しない |

**なぜ試作のパレットを採るか。** 試作の「色の役割は排他」という原則、とりわけ
**スコアに緑・赤を使わない**（中立のスチールグレーで表す）という選択が、
`CLAUDE.md` の「投資判断そのものを自動化・推奨する機能は作らない」という方針の
直接的な表現になっているため。現行の `--color-accent: #38bdf8` にはこの意図が無い。

**なぜ Web フォントを読み込まないか。** 試作が指定する `Zen Kaku Gothic New` /
`Roboto Mono` は外部フォント。CDN 参照は依存と外部通信を増やす
（`~/.claude/rules/security.md`）。このアプリで本当に必要なのは
**数字の桁が揃うこと**であり、それは `--font-mono` ＋ `font-variant-numeric: tabular-nums`
で満たせる。セルフホスト（サブセット化・ライセンス確認・容量）は別タスクとし、
必要になってから判断する。

### 2.2 役割の排他ルール（**守らないと意味が壊れる**）

- **`--color-action` は「操作できる」という意味だけに使う。** 操作できない要素に使わない。
- **`--color-data` は判断を含まない。** スコアに緑・赤を使わない。
  スコアが高いか低いかを色で示すと、それは推奨になる。
- **`--color-positive` / `--color-negative` はポートフォリオの評価損益専用。**
  スコア・増配率・成長率には使わない。
  **色だけで増減を表さない。`▲` `▼` と文言を必ず併記する**（`.claude/rules/frontend.md`）。
- **`--color-brand` はロゴだけ。** 他のどこにも使わない。

### 2.3 ⚠️ 試作からの意図的な逸脱：エラー表示の色 ✅ 確定（2026-08-17）

**試作にはエラー表示の設計が無い**（`role` 一覧に error が無い）。
現行 `frontend/style.css` は `--color-error: #f87171`（赤）を使っている。

**決定: エラー・警告はいずれも `--color-caution`（amber）で示し、赤は評価損益専用に温存する。**

- 赤をエラーにも使うと、ポートフォリオ画面で**評価損益のマイナスとエラー表示が同じ赤**になる。
  「含み損」と「取得に失敗した」を色で見分けられなくなるのは実害が大きい。
- **エラーと警告の区別は色でつけない。** `role="alert"` ＋ 文言 ＋ 枠線で示す。
  これは既存規約「色だけで意味を表さない」と同じ考え方であり、新しい制約ではない。
- 現行の `.warning` が文言に `⚠` を必ず付けている作りはそのまま維持する。
- したがって **`--color-error` トークンは廃止**し、`--color-caution` に統合する。

## 3. タイポグラフィ

### 3.1 フォント

```css
--font-ui: system-ui, -apple-system, 'Segoe UI', 'Hiragino Sans', 'Noto Sans JP', sans-serif;
--font-mono: ui-monospace, 'SFMono-Regular', Consolas, 'Courier New', monospace;
```

**数値・銘柄コード・日付・計算式は必ず `--font-mono`。** UI フォントで数字を出さない
（表の桁が揃わない）。併せて `font-variant-numeric: tabular-nums` を指定する
（現行 `.numeric` で既に使用）。

### 3.2 サイズ

## 4. 余白・角丸・レイアウト

```css
--space-1: 0.25rem; /*  4px */
--space-2: 0.5rem; /*  8px */
--space-3: 0.75rem; /* 12px */
--space-4: 1rem; /* 16px */
--space-5: 1.5rem; /* 24px */
--space-6: 2rem; /* 32px  ページ左右の余白 */

--radius-sm: 0.5rem; /*  8px  ボタン・入力欄・バッジ */
--radius-md: 0.625rem; /* 10px  入れ子の行 */
--radius-lg: 0.75rem; /* 12px  カード（既定） */
--radius-xl: 0.875rem; /* 14px  ポートフォリオのヒーロー・認証カード */
--radius-2xl: 1rem; /* 16px  ダイアログ */

--content-max: 72.5rem; /* 1160px  コンテンツ最大幅（中央寄せ） */
--width-auth-card: 25rem; /* 400px  認証カード幅 */
--dialog-max-width: 58.75rem; /* 940px  解析ダイアログのカード最大幅（T-096） */

--shadow-dialog: 0 24px 64px rgba(0, 0, 0, 0.6);
--dialog-scrim-color: rgba(6, 8, 12, 0.74); /* 解析ダイアログの背景スクリム（T-096） */
--dialog-scrim-blur: 0.1875rem; /* 3px  スクリムのbackdrop-filter（T-096） */
```

> ⚠️ **`--space-3` / `--space-4` は現行と値が変わる。**
> 現行は `--space-3: 1rem` / `--space-4: 1.5rem`。新しい定義では `--space-3: 0.75rem` /
> `--space-4: 1rem` なので、**番号を据え置いたまま値だけ変えると全画面の余白が詰まる。**
> 実装（T-090）では既存の使用箇所をすべて置換すること。

**影は使わない。** 唯一の例外がダイアログ（`--shadow-dialog`）。
面の分離は影ではなく、フラットな面＋ヘアラインの枠線で行う。

### 8.2 アプリシェル

- **ヘッダーは固定（sticky）・半透明＋ぼかし。** 下端はヘアライン。影は使わない。
- ブランド・ナビ・認証エリアを1行に置く。ブランドは 9×26px の `--color-brand` バー（§2.2 の唯一の用途）＋アプリ名＋英字サブ（`Dividend Scoring`、装飾）。
- ナビの現在地は**下線（`--color-action`）・文字色・太さ**の3つで示す（色だけにしない）。
- 認証エリア: 未ログインは塗りの「ログイン」、ログイン済みはアバター（メールの頭文字・中立色）＋メール＋管理者バッジ＋枠線の「ログアウト」（試作 README §1）。
- 背景には中立の `--color-data` を極薄にした環境光と、縦のガイド線を置く。**`--color-action` は使わない**（操作の意味を持つ色のため）。

### 8.3 画面の組み方

- 画面見出しは `<PageHeader>`（英字の索引ラベル＋画面名＋リード文）。**面（パネル）の外**に置き、本体だけをパネルに載せる。
- ボタンは3段: 塗り（主操作。1画面に1つを目安）／枠線 `.button-outline`（副操作）／`.button-ghost`（主操作の隣で目立たせない操作。一覧の「削除」）。銘柄登録フォームの取り込み・年度追加は枠線にし、塗りは「解析して保存」だけにした。
- **数値列は見出しも右寄せ**（`<th className="numeric">`）。値と見出しの縦の流れを揃える。
- 一覧の行は「表示」ボタンを stretched button にして行全体で押せる。銘柄名にも独立したテキストボタンを置き、全文の `title` と文字選択を行オーバーレイより前面で利用できるようにする。
- 解析ダイアログの総合点は `--font-size-hero` の数値だけを主役にし、「総合点」「/ 100 点」は小さく添える（試作 README §Design Principles 1）。
- スコアバーには**10%刻みの目盛り**を入れ、計器として読ませる（全画面共通のアイデンティティ。色は中立のまま）。評価基準の区分表は点数にも同じバーを添え、尺度を一目で読めるようにする。
- 配当推移グラフの金額軸は**円で小数2桁に統一する**（`formatSenAxisTick`。整数円・0円も同じ桁数にし、自動生成目盛りの端数との表記混在を防ぐ。T-112）。

### 8.4 モーション

- 入場（画面・カード・ダイアログ）は「下から少し上がってフェードイン」の1種類だけ。スコアバーは左から伸びる。
- `animation-fill-mode` は `backwards` にする。`both` だと終了後も `transform` が残り、子孫の `position: fixed`（確認ダイアログ）の基準がずれるため。
- `prefers-reduced-motion: reduce` ではすべて実質無効にする。

### 8.5 受入基準

- ✅ §6 の色役割とトークン利用を維持。直値の既存例外は下記の範囲とし、新規の色・余白・フォントサイズにはトークンを使う
- ✅ `npm test` / `npm run typecheck` / `npm run lint` が通る
- ✅ 全画面（検索・解析ダイアログ概要/①/③・評価基準・ポートフォリオ・指標カスタマイズ・銘柄登録・ログイン）を 1280px と 390px で実描画確認（`run-dividend-stock-analysis` スキル。`DSA_VIEWPORT_WIDTH` で幅を変えられる）

**既存の直値の例外（T-111、2026-10-04）。** 全面的なトークン化は行わず、単独部品の寸法や
ビューポートに依存する配置は例外として記録する。意味の違う寸法を同じ余白トークンへ統合すると、
トークン変更で意図しない連動が起こるため。共通の余白・文字サイズ・色を追加する際は引き続き `:root` に定義する。

| 対象 | 既存の直値と理由 |
| --- | --- |
| 検索アイコンの空き | `.search-bar input` の `padding-left: 2.5rem`。アイコンと入力文字の衝突を避ける専用寸法 |
| コンパクトダイアログ | `margin-block: 12vh ...`。デスクトップで画面高さに応じた上空きを取る。640px以下では `--space-2` に上書き済み |
| 部品の寸法 | ブランドバー・チェック・索引・表の列・入力欄・バー・ヒーロータイルの固有幅／高さ（0.3125〜44rem）。共通余白ではなく内容の収まりと見た目を決める |
| ログイン領域 | `calc(100vh - var(--header-height) - 14rem)` と導入文の `max-width: 30rem`。画面高さと文章の行長を調整する |
| 指標行のインデント | `calc(1.375rem + var(--space-4))`。番号アイコンの幅と共通余白を合成する |
| 装飾・アクセシビリティ | 1〜2pxの線、sr-onlyの1px/-1px、背景光のrem寸法・比率、字間・アニメーション・変形値。色や本文の余白／文字サイズの直値ではない |
| 全画面・ブレークポイント | 100vh、60rem、40rem。レイアウトの条件と画面の占有率 |

「直値なし」という旧記載は、上記の現存する例外を無視していたため撤回する。

### 8.6 レビュー指摘の修正（2026-10-04、R-01〜R-15）

- 一覧行は `.company-row` で包含ブロックを明示する。行クリックの成立を `:has()` 対応に依存させない。stretched button の押下時は `transform: none` とする。
- 行オーバーレイは `z-index: 1`、銘柄名・編集・削除操作は `z-index: 2` とする。スコアバーや行末装飾が行クリックを奪わないようにし、行末セル自体は変形しない。
- 備考セルだけに `.metric-notes` を付けて折り返す。保有銘柄の評価額列に列番号を使った備考スタイルを当てない。
- `.metric-table` と `.input-table` は全画面幅で横スクロールを表の内部に収める。ポートフォリオタブは長い名前を折り返し、削除操作はタブ列の下の独立した行に置く（`portfolio-page.md` §9）。
- ナビは全画面幅で細いスクロールバーを表示する。末尾のリンクを隠す常設フェードは付けない。
- T-109: 960px以下のヘッダーはブランド／ナビ＋認証の2段でDOM順を保つ。選択行のホバー色と入力エラー枠を維持する。640px以下の集計は評価額32px・評価損益17pxに縮小する（既存フォントトークン）。
- T-110: レーダーの判定不能は線だけ0へ置き換え、点は描かない。0点と通常点は中立色の点を描く。
- T-112: 文字選択の背景は操作色ではなく中立の `--color-data` を使う。
- 無効ボタンは色に加えて `opacity: 0.6` で区別する。コンポーネントの色指定が無効状態の見た目を消さないようにする。
- 銘柄登録の警告バナーはフォーム直下の警告だけを対象にする。年度表のセル警告は本文のまま表示する。
- 作成・追加・編集ダイアログは実装の `div` 直下の見出し・ラベルに余白と縦並びを適用する。
- 表見出し・取得時刻・レーダー注記・評価基準の境界条件・画面エラーは `--color-text-secondary` で表示し、背景とのコントラストを確保する。
- 文書の `scroll-padding-top` はヘッダーと余白の合計とし、960px以下では2段分を確保する。画面の種類が変わった後にスクロールを先頭へ戻し、同じ画面の検索条件・ダイアログ操作では位置を保つ。
- 回帰検証は `tests/frontend/review-2259ac6.test.ts` と、実Chromeを操作する `tests/browser/review-2259ac6.mjs` に置く。ブラウザ検証はダミーAPI応答を使い、データの更新を行わない。
