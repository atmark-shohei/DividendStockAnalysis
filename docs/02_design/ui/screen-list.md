## 実装済みの構成（2026-07-28 時点）

**URL ルーティングによる2画面。** 画面の選択も銘柄の選択も **URL が正**で、
リロード・共有・戻る/進むで状態が失われない。

| URL           | 画面           | 実装                        |
| :------------ | :------------- | :-------------------------- |
| `/`           | 保存済み銘柄   | `frontend/pages/ListPage`   |
| `/?code=7203` | 同上＋解析結果 | 同上（`code` で銘柄を選択） |
| `/input`      | データ入力     | `frontend/pages/InputPage`  |

### 画面遷移

| 起点             | 操作         | 遷移先                             |
| :--------------- | :----------- | :--------------------------------- |
| どちらの画面でも | nav のリンク | `/` / `/input`                     |
| `/input`         | 解析に成功   | `/?code=<コード>`                  |
| `/input`         | 解析に失敗   | 遷移しない（入力内容を失わせない） |
| `/`              | 「表示」     | `/?code=<コード>`                  |
| `/?code=X`       | X を削除     | `/`（選択解除）                    |

| 機能ID | 内容                 | 状態 | 対応する画面                     |
| :----- | :------------------- | :--- | :------------------------------- |
| F-30   | データ入力・解析タブ | 🟢   | `/input`（`CompanyForm`）        |
| F-32   | 保存済み銘柄タブ     | 🟢   | `/`                              |
| F-34   | 免責文言の常時表示   | 🟢   | footer（両画面）                 |
| F-31   | 評価基準タブ         | 🔴   | 未実装（§ 次に追加するとき参照） |
| F-33   | 銘柄間の横並び比較   | 🔴   | 未実装（§ 次に追加するとき参照） |

### この構成で守っていること

- **画面状態を URL に置く**（`.claude/rules/frontend.md`）。旧実装
  （`reference/legacy-web/`）はタブ切り替えを `class="active"` の付け替えだけで行っており、
  リロード・共有で状態が失われた。**同じ失敗をしていない**
- **URL の解釈は純関数に閉じる。** `frontend/routes.ts`（DOM 非依存・テスト対象）と
  `frontend/use-route.ts`（History API）を分けてある。テストは `tests/frontend/routes.test.ts`
- **ルーティングライブラリを足していない。** 2画面に依存は要らない
  （`~/.claude/rules/security.md`「新しい依存を追加する前に既存で足りないか確認する」）
- **データ取得は `App` と `api.ts` だけ。** `pages/` は props で受け取る（ルート `CLAUDE.md`）
- Worker 側の変更は不要。`wrangler.jsonc` の
  `not_found_handling: "single-page-application"` が `/input` 直打ちを `index.html` へ流す

### この構成のトレードオフ

- **解析に成功すると入力内容は失われる。** `/input` から離れると `CompanyForm` が
  アンマウントされるため。同じ銘柄を修正して再解析するには入力し直しになる。
  データ入力と保存済み銘柄を完全に分ける決定を優先した結果であり、意図的
- 解析直後も POST の戻り値を使わず `GET /api/companies/:code` を取り直している。
  情報源を URL 一本に絞るため。往復が1回増える

## 次に追加するとき決めること（F-31・F-33）

ルーティングは導入済みなので、**追加する画面は URL を1本増やすだけで済む。**

- F-31（評価基準）は `/criteria` で足りる見込み。API を呼ばない静的な説明画面
- F-33（横並び比較）は `/` の複数選択が起点になる想定。選択状態も URL に載せる
  （`/compare?codes=7203,8306` など）。選択 UI・比較画面の遷移は未設計
  （対応する `02_design/ui/pages/*.md` が無い）
- 画面が4つを超えるなら nav の形（横並び / ドロップダウン）を再検討する

## 全画面共通の要件

- 免責文言を常時表示する（投資助言ではない旨）— 実装済み（両画面の footer）
- データ取得中の表示 — **部分的に実装。** 解析結果は「読み込み中…」を出すが、
  一覧の初回取得中の表示（スケルトン等）は無い
- エラー時は「何が起きたか」を表示する — 実装済み（`role="alert"`、両画面共通の位置）。
  「次に何をすればよいか」までは踏み込んでいないものが一部ある（要確認）
- 現在地を色だけで示さない — nav は下線＋背景＋`aria-current="page"`、
  一覧の選択行は背景＋ボタン文言「表示中」＋`aria-pressed`
