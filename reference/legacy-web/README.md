## 仕様書との差分

`docs/01_requirements/scoring-requirements.md` の未解決点に対して、
**実装が事実上の回答になっているもの**と、**実装のほうが間違っているもの**がある。

### 実装が仕様の空白を埋めているもの（採用候補）

| 仕様 §  | 論点 | 実装の挙動 |
| :--- | :--- | :--- |
| §0.1 | 境界値がどちらの区分か | すべて `>=`（**下限以上・上限未満**）。提案した規約と一致 |
| §0.2 | ① の 1〜2% の穴 | `pct > 0 → 1点`。穴は無く 1点 |
| §0.2 | ① の 29〜30% の穴 | `pct >= 20 → 9点`。**上限 29 は 30 の転記ミス**だったと分かる |
| §0.3 | ⑤ ROE が負 | `< 2% → 0点`。問題なし |

### 実装に不具合があるもの（仕様として読むときの注意）

| # | 内容 | 該当 |
| :--- | :--- | :--- |
| 1 | **③ 予想配当性向で赤字企業が満点。** EPS が負 → 配当性向が負 → `pct <= 25` に該当し **10点** | `getPayoutRatioScore` |
| 2 | **③ で無配（配当性向 0%）も満点（10点）。** 高配当スクリーナーとして意図に反する | 同上 |
| 3 | **④ EPS CAGR が説明と違う。** `CRITERIA_DATA` の説明は「直近3年の中央値と5年前3年の中央値で算出」だが、実装は**端点同士の単純比較** | `calculateCsvScores` |
| 4 | **CAGR の期間が固定でない。** `1/yearsDiff` を使うため、データが4年分しかない銘柄と5年ある銘柄が同じ指標として並ぶ。仕様は 5 年固定 | ①④⑦ |
| 5 | **② の「18年遡及」上限が未実装。** 遡及年数に上限がなく、データがある限り数える | ② |
| 6 | **データ欠損とスコア0を区別していない。** 全スコアが `0` 初期化で、計算不能でも 0点として合計に入る。プロジェクト規約（欠損は `null`）に反する | 全指標 |
| 7 | **株価未入力で ⑩ が 0点。** 設計書では `null`（判定不能）に確定済み | `calculateCsvScores` |
| 8 | **金額を `parseFloat` の浮動小数点で扱っている。** 規約は整数（銭）または Decimal | `parseCsvBlocks` ほか |
| 9 | **免責文言が無い。** F-34 は P0 | `index.html` |
| 10 | **予想行の判定が全角括弧の完全一致**（`line.includes('（予想）')`）。表記揺れで無言に実績扱いになる | `parseCsvBlocks` |
| 11 | **TSV の分割調整配当を6列目固定（`cols[5]`）で読む。** 列順が変われば無言で誤った値を取る | `parseTsvData` |
| 12 | **解析エラーを `alert('解析中にエラーが発生しました。')` で潰している。** どの行が読めなかったか分からない（F-06） | `processData` |
| 13 | **スコア表が `CRITERIA_DATA` と判定関数の二重管理。** 現状は一致しているが、片方だけ直せば静かにズレる | `app.js` 末尾 |

### 実装のほうが正しいもの

| 内容 | 該当 |
| :--- | :--- |
| ⑩ の判定に**丸めを使わず生値**で比較している。仕様書の「第2位まで判定に使用」は誤り（5.4951% が 10点になってしまう） | `getDividendYieldScore` |

## Firebase について（要判断）

- **解析するたびに無条件で Firestore へ書き込む。** ユーザーの保存操作が無い。
  `processData` の末尾で `saveStockToFirebase` を必ず呼んでいる。
- **同一ティッカーは `setDoc` で上書き。履歴が残らない。** 過去の解析結果と
  比較できない。
- **認証が無い。** Firestore のセキュリティルールをこのリポジトリでは確認できて
  いない。ルールが開いていれば誰でも読み書きできる。**Firestore を続けるなら**
  新規実装の前に必ず確認すること（localStorage に替えるなら不要）。
